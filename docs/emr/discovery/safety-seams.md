### R1 — verdict: **CONFIRMED, and worse than stated**

- A resus AMPLE / prescribe-dialog allergy (store B) is **invisible outside that episode**: nothing copies B into A; `recordedAllergiesFromTimeline` reads only the current episode's events, so it is invisible even to the **next resus episode for the same patient**, the encounter page, the patient record panel and the SBAR of any other episode.
- An allergy in `patient_allergies` (A) **is** visible to both resus prescribing paths, but only under `ENCOUNTER_ENGINE_LIVE=1`, and only client-side for grab-and-give.
- In practice A has **no live writer**: its only writer is `recordClerkshipVersion`, whose only caller (`lib/encounter/handoff.ts:204-210`) passes a triage-seeded clerking with no allergies. With v1 clerking removed and NCD clerking not writing to the record, A is empty in every real flow. Net effect today: the only working allergy check is in-episode resus.
- "Missing is never normal" gap: A cannot express NKDA or "unable to assess"; B's v1 exposure path never writes NKDA.
- Failing test to write (Phase 0 deliverable): record allergy via `recordResusAllergies` on episode 1 → `loadPersistentAllergiesForEpisode(episode2)` and `loadPatientClinicalRecord(patient)` must contain it (fails today).

## Q8 / R4 — Resus handoff, death-certificate intent, triage intents

### Resus close-out (`app/nurse/resus/_v2/actions-closeout.ts:128-251`, `closeResusV2`)

- Writes timeline events: `handover` (step `post`, payload `{sbar{situation,background,assessment,recommendation}, receiving{unit,cadre}|null, escort, cprOngoing}`, `:170-182`; Zod `SbarSchema :48-53`) + disposition events + `decision: closure {outcomeCode, closureKind:'bedside'}`.
- The payload is **SBAR** (4 fields), not ISBAR — no Identify field; identity lives in `situation` text (`handover.ts` `situation()`).
- Header patch (`:220-234`): `state='concluded'`, `outcome_code`, `disposition`, levels, `pending_encounter_handoff`, optional `encounter_id`.
- Encounter seam (`:199-218`): only when **not died** AND `encounterEngineLive()` AND `triageRecordId` → `openEncounterFromTriage` (`lib/encounter/handoff.ts:88`), which seeds a **draft** clerking from triage (complaint, acuity, vitals; `finalise:false`, `:204-210`). **Nothing from resus is carried**: not the SBAR, AMPLE allergies, drugs given, resus vitals or diagnoses.
- `pending_encounter_handoff` (column `0068_resus_desk_v2.sql:43`, `db/schema/resus.ts:93`): set `true` for a survivor with no linked encounter (flag off, no triage record e.g. `openResusFromIntake`/`openBlankResus`, or seam failure); `false` for deaths. **No reader anywhere** (grep: only the writer + type `lib/resus/v2-record.ts:71`). Dead-letter flag.
- Ordering hazard: the encounter is created **before** `commitResusEvents` (`:202` vs `:235`); a failed commit (e.g. `expectRows` conflict) leaves an encounter unlinked to the episode.

### Death-certificate "intent"

- Not an intent row. It is checklist item `CO-ADT-06` "Certificate of cause of death (pending intent to the encounter record; not built)" (`lib/resus/reference/levels-of-care.ts:334-338`), ticked as a row in `resus_after_death_tasks` (`0068:378+`, `db/schema/resus.ts:402-418`; writer `recordAfterDeathTaskV2` `actions-closeout.ts:524-565`, 24 h window). No cause-of-death model exists (only `ClerkFamilyItem.causeOfDeath` for relatives, `clerkship.ts:91`).
- Death confirmation: `confirmDeathV2` (`_v2/actions-arrest.ts:739-815`) → event `death_confirmed` + header `death_confirmed_at`.

### Existing death record (Workspace D2, ADR 0115)

- `docs/adr/0115-death-read-from-the-records-that-hold-it.md`: **no stored patient-level death column**; `deathsFor(hospitalId, patientIds)` (`lib/workspace/queries.ts:390-440`) reads (a) `resus_episodes` with `death_confirmed_at`, died `outcome_code`, or `disposition ∈ {mortuary,deceased}`, and (b) `encounters.disposition='deceased'` (CHECK `db/schema/scheduling.ts:423`). Latest wins. CSO signature pending; flag unset. Only writer of encounter disposition: `record.ts:190-194` (finalised clerking only — unreachable today).

### Triage recommendation intents

- Shape (`lib/triage/recommend.ts:26-50`): `{code, category ∈ 7, suggestion, rationale, source, seam: 'live'|'pending_intent', confidence}`; `recommend(result, assignedLevel)` (`:69`) is pure.
- **Never stored.** Only consumer is `app/nurse/triage/_components/next-steps.tsx:72`, computed at render; `pending_intent` renders a grey "workflow to follow" badge (`:41-44`). No column in `triage_records` (`db/schema/triage.ts:59-84`); recomputable from `computed_breakdown` + assigned level.

## Prompt-vs-repo disagreements

1. Prompt stack (Prisma, pnpm, `prisma dev`, Edge Functions for writes) ≠ repo (Drizzle, npm, server actions with service-role `db` + app-level scoping; RLS bypassed on these paths).
2. R1 says prescribing reads AMPLE "there"; it reads AMPLE **and** `patient_allergies` (flag-gated), but the table has no live writer.
3. R3 "nothing links an order to a result" — false; FK + one-per-order exist. Acknowledgement genuinely absent.
4. Handover is SBAR, not ISBAR.
5. Death-certificate "intent" is a checklist tick, not a stored intent; `pending_encounter_handoff` is a boolean with no consumer.
6. Triage "intents" are not recorded anywhere — computed at render.
7. Prompt §5 (line 265) "writes the patient-level death record per Workspace D2" contradicts ADR 0115 (no stored column; read from resus + encounter). A new writer must be encounter `disposition='deceased'` or ADR 0115 superseded.
8. Prompt Law 2 "one allergy record": `patient_allergies` exists but needs additive columns (status, verification, assertion NKDA/unable-to-assess, provenance, coded substance) — `0039`/`0040` immutable, so a new migration (next free ≥ 0071).
9. `0039` is GATED; `patient_allergies` is authoritatively created by `0040` with a relationship-based policy (`0040:211-249`), not 0039's hospital policy.

## Risks / order of fixes

- Server-side allergy re-check missing in `recordEmergencyAdministration` — client-only safety gate.
- Silent `[]` on persistent-allergy load failure; race before load resolves.
- Cross-hospital allergy read without hospital filter vs RLS intent.
- Re-clerking duplicates allergy rows (no dedupe/supersession).
- Resus→encounter carries nothing clinical; deaths get no encounter at all.
- Lab release non-transactional; abnormal≡critical conflation will mislabel non-critical abnormals once signed.
- Migration apply state (0039/0040/0050/0051/0068) not verifiable read-only here; confirm with owner.
