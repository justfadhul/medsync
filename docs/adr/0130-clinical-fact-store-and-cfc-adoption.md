# ADR 0130 — The clinical fact store: CFC adoption, as harmonised to this repo

**Status:** Accepted — 2026-09-26. Built on `feat/emr-engine` (Phases 0–6), dark behind `EMR_V1`. GATE A signed as recommended by Fadhul (owner, CSO), 2026-09-26, in session (E1–E10, D-EMR-01–16, D-CFC-01–15, D-NCD-01–17). Records every **[H]** harmonisation of `docs/emr/HARMONISATION.md` §2 and the deviations D1–D3 of `docs/emr/gate-a-proposal.md` §H.1.

## Context

The NCD engine, the resus desk, prescribing and the clerking page each needed the same clinical truth. The repo already held half an EMR (0040, 0050/51) with no live writers, a mutable `clinical_observations` table written by three paths and read by three more, no results acknowledgement, and allergies scattered over two stores. The five specs (PROMPT-ENCOUNTER-EMR, MS-DATA-CFC-001, MS-EMR-CLIN-001, MS-NCD-ENG-001, `clinical-fact-concepts.v1.json`) assumed Prisma, pnpm, `tenant_id` and a hosted dev database. The specs say the repo wins.

## Decision

1. **Adopt MS-DATA-CFC-001 with the v1.1 addendum** (`docs/emr/cfc-v1.1-addendum.md`, `data/emr/clinical-fact-concepts.v1.1.json`). Engines read facts only through `loadFactSnapshot` (`lib/facts/loader.ts`); the fact types, schemas and the generated catalogue live in `lib/facts/**`, canonical units in `lib/units/**`.
2. **Three GATED migrations, additive.** `0071_emr_record_spine.sql` (schema, the access rule, RLS, grants, backfill), `0072_emr_reference_seed.sql` (generated by `scripts/emr/gen-seed.ts`; byte-identical on regeneration), `0073_emr_realtime.sql` (PHI-free `chart:<patient>` broadcasts, the reader role's last grants, `private.allergy_source_text`). 0071 issues no UPDATE or DELETE against an existing row.
3. **Evolve, then add.** Evolved: `encounters` (ADR 0139), `clinical_observations`, `encounter_orders` (`lifecycle legacy|events`), `clinical_cosign_requests` (`sign_note`). New: 21 tables — 7 registries (config, mutable, audited: `clinical_concepts`, `drug_class_tags`, `capabilities`, `facility_capabilities`, `devices`, `test_catalogue`, `diagnosis_terms`) and 14 clinical tables, 13 of them insert-only (`clinical_notes` is mutable only as a draft) — plus 5 `_current` views.
4. **Harmonisations [H]** (mechanism changed, intent kept):
   - **E3.** `clinical_observations` gains the CFC columns, nullable for legacy rows. A guard trigger makes CFC rows (`concept_id IS NOT NULL`) immutable and lets legacy rows make only the resus `active → corrected` move. No backfill mutation: legacy rows and triage `vitals_snapshot` are **projected** into facts by the loader (`lib/facts/project/*`), never copied. New fact rows carry `state='fact'` so the three legacy observation readers never see them.
   - **D-CFC-11.** Finding tokens are `symptom_catalog` ∪ `clinical_concepts` of kind `finding`; `clinical_concepts.symptom_code` gives an overlapping token one identity. The patient booking list is untouched.
   - **E8.** Three workspace lanes (Critical results, Results to review, To co-sign) are added the repo's way — a `LaneId`, a `LANES` entry, an FW-2 branch and a loader — because no lane registry exists.
   - **E1, E2, D-EMR-04, D-EMR-09** are recorded in ADRs 0133, 0131, 0135 and 0139.
5. **Deviations (gate-a-proposal §H.1).** D1: no `private.block_mutation()`; the existing `public.block_modify_append_only()` is reused. D2: backfilled allergies carry `legacy_ref` and no text (SQL cannot produce `lib/encryption.ts` ciphertext); the text is read from the untouched source. D3: `closure_reason` is a code plus `closure_note_ciphertext`; the allergy informant is `informant` beside the CFC `source`; `recorded_by_user_id` is the repo's name.
6. **CFC errata, recorded rather than edited in the spec:**
   - `MedicationFact.status` collided with the envelope status and is `medicationStatus`.
   - `ContextFact.setting` is optional.
   - `PregnancyFact` has no slot for the EDD basis.
   - `rpt.ecg` `device` clashes with the blood-pressure device enum.
   - In `clinical-fact-concepts.v1.json`, `cond.dka`, `cond.hhs` and `cond.hypoglycaemia_in_dm` cite the wrong findacode page; the codes themselves check out.
   - Addendum enum extension: specimen `sputum`; containers `sodium_citrate`, `blood_culture_bottle`, `sterile_container`.
   - ACVPU `C` has no AVPU answer: those triage readings are quarantined with a reason, never dropped, until a concept is signed.
   - `mg/dL` urea is read as urea nitrogen (the spec's factor); a urea-mass report needs its own unit (CSO note).
7. **No clinical numbers.** Critical limits, plausibility bounds, HMIS, IDSR, the pregnancy age range and the fasting definition are `RefEntry` files in `lib/emr/reference/*.ts` (the resus shape) with `status: 'pending_cso'` and the value withheld. The mechanism ships and shows no number. The only numbers are signed ones: unit conversions (CFC §5) and the five unit-mismatch rules (D-CFC-14).

## Consequences

- One vital-sign series, one allergy record (ADR 0135), one problem list: legacy `problem_list`, `encounter_diagnoses`, `encounter_medications` and `encounter_results` are projected read-only, and new writes go only to the new tables.
- Legacy rows stay byte-identical (100+ legacy tables hash-identical before and after 0071 in the harness). Retiring them is a later owner decision after the row counts (O-4) and the allergy re-encryption (O-5).
- Numbers at the gates: 2,400 RLS probes with 0 mismatches; 133 tables compared Drizzle ↔ database; 145 concepts, 21 drug-class tags, 29 capabilities, 35 tests and 85 draft terms seeded; 3,084 EMR tests on the PGlite lane at STOP 4.
- **Open budget items, not hidden:** the loader's p95 is 91 ms at 2,000 facts on PGlite against a 60 ms Postgres budget (measure on the dev project, O-1), and the payload is 1.4 MB against 1 MB because the v1 fact shape repeats the envelope on every fact.
- The `_current` views return the newest version whatever its status; the loader and chart drop `entered_in_error` and `cancelled`. Registries are readable by any signed-in user (non-PHI config).
- Pre-existing Drizzle drift outside the EMR is pinned by name in `tests/emr-db/drizzle-parity.test.ts`, not fixed.
- **Not built:** the NCD engine (MS-NCD-ENG-001) itself; eGFR (D-CFC-06); any hospital-settings store (ADR 0139); the convergence of the legacy TS access resolvers (ADR 0131).

## Alternatives considered

- **A second, clean observation table (the spec's first reading of E3)** — two vital-sign series and a migration of three live writers. Rejected for the guard trigger plus projection.
- **Backfilling legacy rows into the new tables** — it mutates or duplicates the only copy of old data and needs ciphertext SQL cannot make. Projection keeps one list on screen without touching the source.
