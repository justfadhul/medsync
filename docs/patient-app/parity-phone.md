# Patient app v2 · Parity report · Phone (Step 12, draft)

**Status: draft, not signed.** The prompt asks for a signed parity report per platform: every Step 0 item present in v2 or in `renames.json` with a signed reason. This draft is for the owner and the CSO to check and sign.

**How to read it.** Rows follow the signed feature matrix (`docs/patient-app/feature-matrix.md`). Each row says where the feature is now:

- **v2**: rebuilt in v2, behind the flag, at the step named.
- **Kept**: the current screen is unchanged and still serves. Nothing is lost, but it has no v2 design yet.
- **Gap**: the matrix asked for a v2 change that this slice did not build.
- **Deferred**: the owner deferred it.

**The phone's default since 18 Nov 2026 (ADR 0524, the owner's choice).** The `appV2Mobile` switch is gone: every row marked v2 below is what the phone shows, and every Kept row is the current screen, reachable from the v2 shell. Nothing is dropped: `renames.json` holds no removals (`dropped: []`) and every route still exists. Care mode rows are built and locked (`careMode`, Gate CG). Removed code, all replaced by v2: the old "your day" Home, the simulated pay-now step when asking for a day, the MedSync wordmark.

**In short:** 25 rows have v2 work, 24 keep the current screen, 15 carry a gap, 1 deferred.

**Finish pass 1 (18 Nov 2026, not signed):** rows 1.1, 1.3, 1.11 and 3.1 changed; 3.4, 3.7, 3.10 and the Wellness row say how the kept screens are reached. The header count (1.3) and the wordmark (1.11) are closed; the tab bar (1.1) is built for Visit mode and still carries a gap for Care mode's places. Seen in a browser at phone width on fixtures (`docs/patient-app/screens/phone-finish/`), not on a device.
